# P2 (part 2): gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The single public entry of the backend: the desktop app talks only to `gateway` (port 8080), which checks tokens against auth-profile's JWKS, rate-limits, applies CORS and request ids, and proxies `/v1/auth/**` and `/v1/profile` to auth-profile.

**Architecture:** Copy of `services/_templates/go` without the database (`internal/db`, `items`, `migrations`, sqlc removed). Gin for its own routes and middleware; `net/http/httputil.ReverseProxy` for forwarding. A routing table (`internal/routes`) maps path prefixes to an upstream and an auth mode. JWTs are verified with `golang-jwt/jwt/v5` and a cached JWKS (`MicahParks/keyfunc/v3`, refreshed on unknown kid). Rate limits are fixed one-minute windows in Redis (`go-redis/v9`).

**Spec:** `docs/ROADMAP.md` § P2 (gateway), `docs/SERVICES.md` § gateway, `docs/diagrams/02-gateway.md`, `docs/ARCHITECTURE.md` § Authentication, ADR-11/12/18.

## Global Constraints
- No business logic and no database; the same JWT is forwarded unchanged (services verify it again).
- A request with a bad, expired, foreign-key or wrong-issuer token never reaches a service: 401 problem+json.
- Every error is RFC 9457 problem+json with `trace_id`; `/health/live`, `/health/ready` (Redis + JWKS loaded), `/metrics`.
- Config from env only: `PORT=8080`, `REDIS_URL`, `JWKS_URL`, `JWT_ISSUER`, `UPSTREAM_AUTH_PROFILE_URL`, `CORS_ORIGINS`, rate limits.

## Routing table (P2)
| Prefix | Upstream | Auth |
| --- | --- | --- |
| `/v1/auth/` | auth-profile | optional: checked when present (Lichess linking, unlink) |
| `/v1/profile` | auth-profile | required |
| anything else | none | 404 problem |
`/.well-known/jwks.json` is not routed: it is service-to-service.

## Rate limits (per minute, env-overridable)
- Per IP, all routes: 300. Per IP on sign-in routes (`/v1/auth/guest`, `/v1/auth/email/*`, `/v1/auth/lichess/*`): 20.
- Per user (`sub`): guest 60, user 300.
- 429 problem with `Retry-After` = seconds to the end of the window. Redis down: fail open with a warning log (sign-in must keep working; the per-address caps in auth-profile still hold).

## CORS
Origins from `CORS_ORIGINS` (dev: `http://localhost:1420,tauri://localhost,http://tauri.localhost`); headers `Authorization, Content-Type, Idempotency-Key`; exposes `Retry-After, X-Request-Id`; preflight answered by the gateway.

## Review Focus
1. Token with `alg: none` or HS256 signed with the public key: refused.
2. Unknown `kid` after a key rotation: JWKS refetched once (rate-limited), then accepted.
3. Path tricks (`/v1/profile/../admin`, `//v1/profile`, encoded slashes) cannot reach an unrouted path or skip auth.
4. Hop-by-hop and spoofable headers (`X-Forwarded-For` from the client) are not trusted.
5. Upstream down: 502 problem, not a hang (timeouts).

### Task 1: Scaffold `services/gateway` from the Go template
Copy, rename module, remove database pieces; `/health/*`, `/metrics`, problem helpers kept. Compose (`gateway` in `full`, depends on auth-profile healthy and Redis), CI filter, release image. Test: health and 404 problem.

### Task 2: Routing table and proxy
`internal/routes`: `Route{Prefix, Upstream *url.URL, Auth Mode}`; longest prefix wins; path cleaned before matching. Tests (httptest upstream): forwards method, path, query, body and `Authorization`; adds `X-Request-Id`, `traceparent`, `X-Forwarded-For` (client value dropped); unknown path 404; upstream down 502; upstream slow → 504 after the timeout.

### Task 3: JWT check
`internal/auth`: `Verifier.Verify(raw) (Claims, error)` with RS256 only, issuer check, leeway 30 s; JWKS from `JWKS_URL` cached with background refresh and refresh-on-unknown-kid. Tests: valid passes and reaches upstream; expired, wrong issuer, foreign key, `alg: none`, HS256-with-public-key, garbage → 401 and the upstream counter stays 0; required route without a token → 401; optional route without a token → forwarded.

### Task 4: Rate limit and CORS
`internal/limit` with Redis (Testcontainers). Tests: 21st sign-in call from one IP in a minute → 429 with `Retry-After`; per-user limit keyed by `sub`; Redis stopped → requests still pass. CORS preflight from an allowed origin → 204 with headers; other origin → no CORS headers.

### Task 5: End to end
`make smoke` signs in by email **through the gateway** (code from Mailpit), reads the profile through it, and checks a bad token is refused at the gateway. README, SETUP, ROADMAP status.
